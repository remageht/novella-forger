# novella-forger

Перевод реальных историй людей в фантастические новеллы через метафоры мира и правила Хрониста.

> **Правило №1 Хрониста:** события всегда становятся метафорами мира, имена всегда даются по поступкам `[Суть поступка + ранг]` без реальных имен.

---

## 🛠 Стек технологий

- **Frontend (`web/`)**: Vite, React 18, TypeScript, Tailwind CSS, Lucide Icons, React Markdown.
- **Backend (`server/`)**: Node.js, Express, TypeScript, `@google/genai` (модель `gemini-2.5-flash`), `dotenv`, `cors`.
- **Хранилище**: чисто файловое (без БД), сохранение в `stories/output/YYYY-MM-DD-slug.md`.
- **Автосейв**: сохранение markdown с шапкой + автоматический `git add` и `git commit`.

---

## 🔑 Настройка API-ключа

Для работы генератора требуется API-ключ Gemini (модель `gemini-2.5-flash`).

1. Получите бесплатный ключ в [Google AI Studio](https://aistudio.google.com/).
2. Создайте файл `.env` в корне проекта (или скопируйте из шаблона):
   ```bash
   cp .env.example .env
   ```
3. Откройте `.env` и укажите ваш ключ:
   ```env
   GEMINI_API_KEY=ваш_ключ_здесь
   PORT=3001
   ```

*(Файл `.env` добавлен в `.gitignore` и защищен от попадания в репозиторий).*

## 🌟 Возможности веб-MVP

1. **Форма ковки:**
   - Поле для ввода реальной истории (от 5 предложений) со счетчиком предложений.
   - **Режим «Ответить на вопросы» (Интервью Хрониста):** пошаговый диалог с Хронистом (1 короткий вопрос за раз, 3–6 ответов пользователя). После завершения интервью Хронист собирает связный текст из 5–8 предложений, который подставляется в форму и далее идёт по стандартному пути: план → ревью → письмо.
   - Выбор жанра: `авто`, `культивация`, `исекай/трансмиграция/переселение душ`, `постапокалипсис`, `маго-индустриализация`, `магия`.
   - Кнопка быстрой вставки тестового примера.
2. **Логика Хрониста (две фазы):**
   - **Фаза 1 — План (15-30 сек):** разбор хронологии → жанр-доминант → метафоры мира → карта имен `[Суть поступка + ранг]` → структура 6 глав.
   - **Экран ревью плана:** видно карту имен, события и мораль; имена можно править перед письмом.
   - **Фаза 2 — Письмо глав потоком:** текст глав дописывается вживую по мере генерации, слева — прогресс по главам.
3. **Чтение, слушание и экспорт:**
   - Поглавное чтение с вкладками или режим сплошного текста.
   - Кнопка **«Слушать»** — озвучка новеллы голосом браузера (Web Speech API).
   - Наглядная **Карта имен** с расшифровкой роли каждого участника.
   - Кнопки **«Копировать .md»** и **«Скачать .md»**.
4. **Файловый автосейв и Git:**
   - Сервер автоматически сохраняет готовую новеллу в `stories/output/YYYY-MM-DD-slug.md`.
   - Сервер сразу делает `git add stories/output/...` и `git commit -m "novella: <slug>"` (push выполняется вручную при необходимости).
5. **Лента Хроник:**
   - Вкладка «Лента» отображает все ранее сохраненные новеллы из `stories/output/` для быстрого перечитывания.

## 🧪 Демо-режим (без ключа)

Если `GEMINI_API_KEY` не задан, сервер работает в демо-режиме:
- `POST /api/plan` и `POST /api/write` (а также legacy `POST /api/generate`) отдают пример из `stories/example`-контента с бейджем «Демо-режим»,
- конвейер при этом настоящий: план, стриминг глав, сохранение файла в `stories/output/` и git-коммит,
- диалог интервью в демо использует заготовки вопросов и склейку ответов пользователя без выдуманных фактов,
- шапка сайта показывает «Требуется ключ».

Для живой генерации укажите ключ в `.env` и перезапустите сервер.

## 🛡 Защита от абуза

- `POST /api/plan` — **12 запросов в час с одного IP**, `POST /api/write` — **60**, `POST /api/generate` — **10** (`express-rate-limit`).
- `POST /api/interview/start` — **20 запросов в час с одного IP**, `POST /api/interview/answer` — **60**.
- Сессии планов и интервью живут 30 минут (in-memory, TTL-очистка), `/api/write` требует валидный `planId`.
- Ключ Gemini живет только на сервере, фронт ходит через `/api`.

## 📚 Справочники Хрониста (references/)

Сервер автоматически подкладывает их в промпт при генерации:

- `references/metafora-katalog.md` — каталог «событие → метафора» по всем жанрам (всегда)
- `references/imena.md` — банк имен по ролям + правила проверки (всегда)
- `references/kultivacia.md`, `isekai.md`, `postapokalipsis.md`, `mago-industria.md`, `magiya.md` — жанровые справочники

Выбор: жанр из формы → его справочник; «авто» → все жанровые файлы.
Файлы читаются при каждом запросе — правки применяются без перезапуска сервера.

## 🐳 Прод-деплой

### Вариант 1: Docker Compose (VPS или локально)

```bash
# из корня репозитория (.env рядом или GEMINI_API_KEY в окружении)
GEMINI_API_KEY=ваш_ключ docker compose up -d --build
# http://localhost:3001 — API + фронт в одном контейнере
```

### Вариант 2: готовый образ из GHCR

Каждый push в `main` публикует `ghcr.io/remageht/novella-forger:latest`
(workflow `.github/workflows/docker-publish.yml`; тег `v*` → версионный образ).

```bash
docker run -d --name novella -p 3001:3001 \
  -e GEMINI_API_KEY=ваш_ключ \
  -v novella-stories:/app/stories/output \
  ghcr.io/remageht/novella-forger:latest
```

Первый образ появится после первого пуша workflow. Видимость пакета:
GitHub → Packages → novella-forger → Settings.

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `GEMINI_API_KEY` | ключ Gemini; пусто = демо-режим | — |
| `PORT` | порт сервера | 3001 |
| `DISABLE_GIT_COMMIT` | `1` = не коммитить автосейвы (для тестов/CI) | выкл |
| `TRUST_PROXY` | доверять X-Forwarded-For (за nginx/Cloudflare) | выкл |
| `CORS_ORIGIN` | разрешенные origin через запятую (если фронт отдельно) | выкл (same-origin) |

### CI

`.github/workflows/ci.yml` на каждый push/PR: сборка → смоук-тест API → сборка Docker-образа.
